STEP 7 — SECURITY GROUP FIX: Enable kubectl port-forward and exec
═══════════════════════════════════════════════════════════════════

MANDATORY before starting port-forward. Without this, port-forward and exec
both fail with: "error upgrading connection: dial tcp ...:10250: i/o timeout"

WHY: EKS auto-creates a second AWS-managed cluster security group (separate from the
one we defined in Terraform). The control plane uses THIS managed SG to reach the
kubelet API on port 10250 on each worker node. Without an ingress rule from the
managed SG to our worker node SG, all kubelet traffic is silently dropped.

7a) Get the worker node security group ID:
    NODE_SG=$(aws ec2 describe-security-groups \
      --region ap-south-1 \
      --filters "Name=group-name,Values=phantom-dev-node" \
      --query "SecurityGroups[0].GroupId" \
      --output text)
    echo "Node SG: $NODE_SG"

7b) Get the AWS-managed EKS cluster security group:
    MANAGED_CLUSTER_SG=$(aws eks describe-cluster \
      --name phantom-dev \
      --region ap-south-1 \
      --query "cluster.resourcesVpcConfig.clusterSecurityGroupId" \
      --output text)
    echo "Managed Cluster SG: $MANAGED_CLUSTER_SG"

7c) Add the missing ingress rule:
    aws ec2 authorize-security-group-ingress \
      --region ap-south-1 \
      --group-id "$NODE_SG" \
      --protocol -1 \
      --source-group "$MANAGED_CLUSTER_SG"

    If you get "InvalidPermission.Duplicate", the rule already exists — continue.

7d) Verify (must be a non-empty JSON array):
    aws ec2 describe-security-groups \
      --region ap-south-1 \
      --group-ids "$NODE_SG" \
      --query "SecurityGroups[0].IpPermissions[?UserIdGroupPairs[?GroupId=='$MANAGED_CLUSTER_SG']]" \
      --output json

═══════════════════════════════════════════════════════════════════
STEP 12 — SOCAT BRIDGE: Expose API Gateway to the Browser
═══════════════════════════════════════════════════════════════════

WHY: kubectl port-forward only binds to localhost:8080. The user's browser
(running on their Windows/Mac machine) cannot reach localhost on the EC2 box.
socat bridges public port 9090 → localhost:8080 so the browser can reach the API.

12a) Install socat if not present:
    which socat || apt-get install -y socat

12b) Start socat in a tmux window:
    tmux new-window -n socat
    tmux send-keys -t socat "socat TCP-LISTEN:9090,fork,reuseaddr TCP:127.0.0.1:8080" Enter
    sleep 2

12c) Verify the bridge works:
    PUBLIC_IP=$(curl -s http://checkip.amazonaws.com)
    curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 "http://${PUBLIC_IP}:9090/healthz"
    # Expected: 200

    If this returns 000 or times out, the AWS Security Group may not allow
    inbound TCP on port 9090. Add the rule:
        VPC_ID=$(aws eks describe-cluster --name phantom-dev --region ap-south-1 \
          --query "cluster.resourcesVpcConfig.vpcId" --output text)
        SG_ID=$(aws ec2 describe-security-groups --region ap-south-1 \
          --filters "Name=vpc-id,Values=$VPC_ID" "Name=group-name,Values=phantom-dev-node" \
          --query "SecurityGroups[0].GroupId" --output text)
        aws ec2 authorize-security-group-ingress --region ap-south-1 \
          --group-id "$SG_ID" --protocol tcp --port 9090 --cidr 0.0.0.0/0 2>/dev/null || true
        aws ec2 authorize-security-group-ingress --region ap-south-1 \
          --group-id "$SG_ID" --protocol tcp --port 5173 --cidr 0.0.0.0/0 2>/dev/null || true
