PHANTOM — Full System Recovery Prompt
For: Codex CLI (run on EC2, inside tmux)
Context: Infrastructure (EKS, RDS, Redis) already exists. No Terraform or ECR push needed.
Goal: Get everything running again and show live drift events on the frontend dashboard.

SANDBOX NETWORK LIMITATION:
If any `aws eks`, `aws ec2`, `terraform`, or `aws ecr` command fails with:
  "Could not connect to the endpoint URL: https://eks.ap-south-1.amazonaws.com/..."
This is a CONNECTIVITY LIMITATION of the Codex sandbox — not an AWS credential error.
DO NOT retry endlessly. Instead: output the exact command and ask the user to run it
in their host SSH terminal, then wait for the user to confirm before continuing.

═══════════════════════════════════════════════════════════════════
STEP 0 — GIT PULL (always first)
═══════════════════════════════════════════════════════════════════

    cd /root/phantom-ebpf
    git fetch origin
    git checkout main
    git pull --ff-only origin main
    git log --oneline -3

Do not proceed until pull succeeds.

═══════════════════════════════════════════════════════════════════
STEP 1 — FULL SYSTEM STATUS CHECK
═══════════════════════════════════════════════════════════════════

Run every check below. Print ALL output. Do not skip any.

1a) tmux sessions:
    tmux list-windows -a 2>/dev/null || echo "No tmux sessions"

1b) kubectl pods:
    kubectl get pods -n phantom -o wide 2>/dev/null || echo "kubectl not connected"
    kubectl get pods -n phantom-eval -o wide 2>/dev/null || echo "phantom-eval: no pods"

1c) Port-forward alive?
    curl -s -o /dev/null -w "port-forward healthz: %{http_code}\n" --max-time 5 http://localhost:8080/healthz

1d) socat bridge alive?
    PUBLIC_IP=$(curl -s http://checkip.amazonaws.com)
    curl -s -o /dev/null -w "socat bridge healthz: %{http_code}\n" --max-time 5 "http://${PUBLIC_IP}:9090/healthz"

1e) Frontend alive?
    curl -s -o /dev/null -w "frontend: %{http_code}\n" --max-time 5 http://localhost:5173

1f) Database has drift events?
    since=$(date -u -d '24 hours ago' '+%Y-%m-%dT%H:%M:%SZ')
    curl -s "http://localhost:8080/api/v1/drift-events?since=${since}&limit=5" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" | python3 -m json.tool

Based on the output above, decide what needs to be (re)started in the steps below.
If a component is already running and healthy, SKIP its step.

═══════════════════════════════════════════════════════════════════
STEP 3 — WAIT FOR PODS (if pods not Running/Ready)
═══════════════════════════════════════════════════════════════════

If pods are in Pending/ContainerCreating/CrashLoopBackOff:

3a) Check what's wrong:
    kubectl describe pods -n phantom | grep -A5 "Warning\|Error\|Reason"
    kubectl logs -n phantom -l app=phantom-api-gateway --tail=30

3b) If pods are healthy but just starting, poll every 30s (max 10 minutes):
    kubectl rollout status deployment/phantom-api-gateway -n phantom --timeout=600s
    kubectl rollout status deployment/phantom-causal-engine -n phantom --timeout=600s

3c) Required pod list before proceeding:
    kubectl get pods -n phantom
    # phantom-api-gateway     1/1 Running  (2 replicas)
    # phantom-ebpf-agent      1/1 Running  (1 per node)
    # phantom-causal-engine   1/1 Running
    # phantom-sbom-service    1/1 Running
    # phantom-report-generator 1/1 Running

DO NOT proceed to Step 4 until all pods above are Running.

═══════════════════════════════════════════════════════════════════
STEP 4 — PORT-FORWARD (if localhost:8080 returned 000 or refused)
═══════════════════════════════════════════════════════════════════

Kill any stale port-forward first:
    pkill -f "kubectl port-forward" 2>/dev/null || true
    sleep 2

Start in a dedicated tmux window:
    tmux new-window -n pf 2>/dev/null || true
    tmux send-keys -t pf "kubectl port-forward svc/phantom-api-gateway 8080:8080 -n phantom" Enter
    sleep 6

Verify:
    curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 http://localhost:8080/healthz
    # Expected: 200

If still 000, check pf window:
    tmux capture-pane -t pf -p | tail -15

═══════════════════════════════════════════════════════════════════
STEP 5 — SOCAT BRIDGE (if public:9090 returned 000 or refused)
═══════════════════════════════════════════════════════════════════

Kill any stale socat:
    pkill -f "socat.*9090" 2>/dev/null || true
    sleep 2

Install socat if missing:
    which socat || apt-get install -y socat

Start in a dedicated tmux window:
    tmux new-window -n socat 2>/dev/null || true
    tmux send-keys -t socat "socat TCP-LISTEN:9090,fork,reuseaddr TCP:127.0.0.1:8080" Enter
    sleep 3

Verify:
    PUBLIC_IP=$(curl -s http://checkip.amazonaws.com)
    curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 "http://${PUBLIC_IP}:9090/healthz"
    # Expected: 200

If 000, check Security Group allows TCP 9090 inbound (see main CODEX_DEPLOY_PROMPT.txt Step 12).

═══════════════════════════════════════════════════════════════════
STEP 6 — FRONTEND (if localhost:5173 returned 000 or refused)
═══════════════════════════════════════════════════════════════════

6a) Ensure .env.local is correct:
    PUBLIC_IP=$(curl -s http://checkip.amazonaws.com)
    cat > /root/phantom-ebpf/frontend/.env.local <<EOF
VITE_API_BASE_URL=http://${PUBLIC_IP}:9090
VITE_DEV_TOKEN=dev-bypass-token-for-local-testing
VITE_USE_MOCK_DATA=false
EOF
    cat /root/phantom-ebpf/frontend/.env.local

6b) Kill any stale Vite process:
    pkill -f "vite" 2>/dev/null || true
    sleep 2

6c) Start frontend in a dedicated tmux window:
    tmux new-window -n frontend 2>/dev/null || true
    tmux send-keys -t frontend "cd /root/phantom-ebpf/frontend && npm run dev -- --host" Enter
    sleep 8

6d) Verify:
    curl -s -o /dev/null -w "%{http_code}\n" --max-time 8 http://localhost:5173
    # Expected: 200

6e) Print dashboard URL:
    PUBLIC_IP=$(curl -s http://checkip.amazonaws.com)
    echo "Dashboard: http://${PUBLIC_IP}:5173"
    echo "API:       http://${PUBLIC_IP}:9090"

═══════════════════════════════════════════════════════════════════
STEP 7 — SEED DRIFT EVENTS (if DB returned empty items:[])
═══════════════════════════════════════════════════════════════════

The frontend only shows data if there are drift events in the database.
If Step 1f returned `"items": []`, seed them now.

7a) Start live_attack_stream.py in a tmux window:
    tmux new-window -n stream 2>/dev/null || true
    tmux send-keys -t stream "cd /root/phantom-ebpf && python3 live_attack_stream.py --url http://localhost:8080 --interval 5 --count 100" Enter
    sleep 12

7b) Verify events appear in the DB:
    since=$(date -u -d '5 minutes ago' '+%Y-%m-%dT%H:%M:%SZ')
    EVENT_COUNT=$(curl -s "http://localhost:8080/api/v1/drift-events?since=${since}&limit=20" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" | \
      python3 -c "import sys,json; print(len(json.load(sys.stdin).get('items',[])))" 2>/dev/null || echo 0)
    echo "Events in DB: ${EVENT_COUNT}"
    # Expected: > 0

7c) If live_attack_stream.py is missing or fails, use mock_agent.py as fallback:
    cd /root/phantom-ebpf
    python3 mock_agent.py &
    sleep 20
    kill %1 2>/dev/null || true
    # Verify again:
    since=$(date -u -d '5 minutes ago' '+%Y-%m-%dT%H:%M:%SZ')
    curl -s "http://localhost:8080/api/v1/drift-events?since=${since}&limit=5" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" | python3 -m json.tool

═══════════════════════════════════════════════════════════════════
STEP 8 — CREATE AN INCIDENT (so the Incidents page is not empty)
═══════════════════════════════════════════════════════════════════

8a) Fetch required IDs:
    since=$(date -u -d '30 minutes ago' '+%Y-%m-%dT%H:%M:%SZ')
    DRIFT_EVENT_ID=$(curl -s "http://localhost:8080/api/v1/drift-events?since=${since}&limit=1" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" | \
      python3 -c "import sys,json; d=json.load(sys.stdin); print(d['items'][0]['event_id'] if d.get('items') else '')")

    SNAPSHOT_ID=$(curl -s "http://localhost:8080/api/v1/bdg/snapshots" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" | \
      python3 -c "import sys,json; d=json.load(sys.stdin); print(d['items'][0]['snapshot_id'] if d.get('items') else '')")

    echo "DRIFT_EVENT_ID=${DRIFT_EVENT_ID}"
    echo "SNAPSHOT_ID=${SNAPSHOT_ID}"

    NOTE: If SNAPSHOT_ID is empty, the BDG snapshot has not been created yet.
    In that case, skip to Step 9 — the dashboard drift feed still works without incidents.

8b) Create the incident (only if both IDs are non-empty):
    INCIDENT_RESPONSE=$(curl -s -X POST "http://localhost:8080/api/v1/incidents" \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" \
      -d "{
        \"title\": \"Supply Chain Attack: Dependency Confusion on emailservice\",
        \"classification\": \"suspicious\",
        \"tenant_id\": \"00000000-0000-0000-0000-000000000001\",
        \"snapshot_id\": \"${SNAPSHOT_ID}\",
        \"summary\": \"PHANTOM eBPF agent detected an unexpected executable and network beacon from emailservice consistent with a dependency confusion supply chain attack.\",
        \"drift_event_ids\": [\"${DRIFT_EVENT_ID}\"],
        \"tags\": [\"supply-chain\", \"dep-confusion\", \"emailservice\"]
      }")
    echo "$INCIDENT_RESPONSE" | python3 -m json.tool

    INCIDENT_ID=$(echo "$INCIDENT_RESPONSE" | python3 -c "import sys,json; print(json.load(sys.stdin).get('incident_id',''))")
    REVISION=$(echo "$INCIDENT_RESPONSE" | python3 -c "import sys,json; print(json.load(sys.stdin).get('revision',1))")

8c) Confirm the incident:
    curl -s -X PATCH "http://localhost:8080/api/v1/incidents/${INCIDENT_ID}" \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer dev-bypass-token-for-local-testing" \
      -d "{\"classification\": \"confirmed\", \"expected_revision\": ${REVISION}}" | python3 -m json.tool
